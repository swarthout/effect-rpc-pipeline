# Documentation website

The package website is a Foldkit application on Effect 4. Pages are rendered to HTML during the build and hydrated in the browser. GitHub Pages serves the resulting files without a backend.

## Development

Use the same Node version as the library. From the repository root:

```sh
npm ci
npm run build
npm ci --prefix website
npm run dev --prefix website
```

Open `http://127.0.0.1:4173/effect-rpc-pipeline/`. The dev server renders routes through Foldkit's server entry. Restart it after editing shared Markdown to regenerate content.

```sh
npm run check --prefix website
cd website
npx playwright install chromium
npm run test:browser
```

`check` compiles documentation content, checks types, tests the application state transitions and search, builds every static page, and verifies local links, anchors, assets, metadata, and the sitemap. Browser tests exercise the built files, including hydration, navigation, clipboard, search, themes, mobile layout, and reading without JavaScript.

To inspect the production output, run `npm run preview --prefix website` after building. Browser tests require port 4173 to be free; they start and stop their own preview server.

## Content

Edit the root README, `docs/guides/`, or the library source comments. `scripts/content.ts` selects sections from those files into focused website pages. The README remains a standalone introduction. The complete API reference comes from `docs/api/`, generated by the library's `npm run docs:generate` command. Run `npm run build && npm run docs:generate` from the repository root after API changes.

Markdown is parsed and validated by `@foldkit/markdown`. Shiki highlights code during the build. The browser receives compiled content and a local search index. Fonts are self-hosted. There are no analytics or third-party runtime requests. The dependency demo is an illustrative simulation, controlled through Foldkit's Model, Messages, and Commands.

Generated content, static output, and browser artifacts are ignored by Git. They are not included in the npm package. The website's dependency tree is separate from the library and its examples; its overrides align Foldkit's exact Effect 4.0.0 peer declarations with the tested 4.0.6 baseline.

## GitHub Pages

The `Documentation website` workflow validates pull requests and deploys successful builds on `main`. In the repository's Settings → Pages, select **GitHub Actions** as the build source. The site URL is `https://swarthout.github.io/effect-rpc-pipeline/`.

The default base path is `/effect-rpc-pipeline/`. For a custom domain or a root-hosted preview, set `SITE_BASE=/` for the entire build. Set `SITE_ORIGIN=https://your-domain.example` to generate matching canonical URLs and sitemap entries. Base paths must start and end with `/`. Configure the domain in GitHub Pages and add its `CNAME` file to `public/` when adopting one.

Each route has its own `index.html`; deep links work without SPA rewrites. `404.html` renders a missing-page view rather than redirecting to the homepage. `.nojekyll` preserves build assets. The browser uses Foldkit routing for subsequent navigation.

The implementation follows the static generation and Markdown patterns in [Foldkit](https://foldkit.dev/). The local `repos/foldkit` checkout is a read-only implementation reference, not a runtime dependency.
